# /pollens-compare — 후보 공약 비교표 출력

`/pollens` 오케스트레이터에서 호출하거나 단독으로 실행한다.
`electionType`을 입력받아 비교표 하나를 출력하고 종료한다.

**오케스트레이터에서 호출 시** 대화 컨텍스트에 다음 값이 전달되어 있다:
- `electionType` — 비교할 선거 유형
- `readingMode` — PDF 읽기 모드 (1 또는 2)
- `personaContext` — 사용자 페르소나/관심분야 (null이면 Step 4.5 비활성화)

---

## 금지 표현 (FORBIDDEN — 절대 사용 금지)

다음 표현은 이 스킬 실행 중 **어떤 상황에서도 사용하지 않는다**:

- `1위`
- `가장 적합`
- `추천`
- `승자`
- `점수`
- `더 나은 후보`
- `좋은 후보`

AI는 정보만 제공한다. 판단·추천·순위는 절대 표시하지 않는다.

---

## Step 0: 프로젝트 루트 확인

Bash 도구로 `git rev-parse --show-toplevel` 을 실행해 PROJECT_ROOT를 얻는다.
이후 모든 파일 경로는 `<PROJECT_ROOT>/...` 형식으로 구성한다.

---

## Step 1: electionType 확인

대화 컨텍스트에서 `electionType` 값을 확인한다 (도지사|시장|도의원|시의원|교육감).

값이 없으면 묻는다:

```
어떤 선거의 후보 공약을 비교할까요?
1. 도지사
2. 시장
3. 도의원
4. 시의원
5. 교육감
```

---

## Step 2: 후보 목록 추출

`<PROJECT_ROOT>/data/meta.json` 파일을 읽는다.

`candidates` 배열에서 해당 `electionType` 후보를 모두 추출한다.

후보가 없으면:

```
이 선거 데이터가 없습니다. /pollens-collect 를 실행해주세요.
```

---

## Step 3: PDF 읽기

후보를 `ballotNumber` 오름차순으로 정렬한다.

### Step 3a: 읽기 모드 확인

대화 컨텍스트에 `readingMode` 값이 이미 설정되어 있으면 그 값을 사용한다 (질문하지 않음).

설정되어 있지 않은 경우 (단독 실행 시)에만 다음을 출력하고 사용자 선택을 기다린다:

```
공보(선거공보물)도 함께 읽을까요?
1. 5대공약만  — 후보당 PDF 1개, 빠름
2. 공보 포함  — 후보당 PDF 2개, 이미지 PDF 전체 읽기
              (후보 1인당 약 20~40페이지 추가 소모)
```

### Step 3b: 후보별 PDF 읽기

**1번(5대공약만) 선택/설정 시** — 각 후보에 대해:
- `pdfPath`가 있으면: `<PROJECT_ROOT>/<pdfPath>` 경로의 PDF를 Read 도구로 읽는다.
- `pdfPath`가 없고 `pbinfoPdfPath`가 있으면: `<PROJECT_ROOT>/<pbinfoPdfPath>` 경로의 PDF를 Read 도구로 읽는다 (fallback).
- 둘 다 없으면: 공약 셀에 `(공약 파일 없음)` 표시.

**2번(공보 포함) 선택/설정 시** — 각 후보에 대해:
- `pdfPath`가 있으면: `<PROJECT_ROOT>/<pdfPath>` 경로의 PDF를 Read 도구로 읽는다.
- `pbinfoPdfPath`가 있으면: `<PROJECT_ROOT>/<pbinfoPdfPath>` 경로의 공보 PDF를 Read 도구로 읽는다. 10페이지 이하이면 한 번에 읽고, 초과이면 20페이지씩 분할해 전체를 읽는다. 읽기에 실패하면 공약 셀에 `(공보 읽기 실패)` 표시.
- 아무 PDF도 없으면: 공약 셀에 `(공약 파일 없음)` 표시.

**QR코드 전용 공약 처리:**

PDF를 읽은 후 실질적인 공약 텍스트가 매우 빈약하거나, "QR코드" 언급만 있고 공약 내용이 없다고 판단되면:
1. WebSearch 도구로 `"[후보자 이름]" 공약 2026 [electionType]` 검색한다.
2. 검색 결과에서 사실 정보만 추출해 공약 셀에 기재하고 출처(매체명, 날짜)를 명시한다.
3. WebSearch 결과도 없으면 공약 셀에 다음을 표시한다:
   `(공약 확인 불가 — QR코드 전용 공보)`
   표 아래에 `pbinfoUrl` 링크를 별도 안내한다.

---

## Step 4: 공약 비교표 출력

후보자를 `ballotNumber` 오름차순으로 정렬한다.

### 기호번호 중복 처리 (중선거구)

같은 `electionType` 내에서 `ballotNumber`가 동일한 후보가 2명 이상 있으면:
- meta.json 등록 순서대로 `-가`, `-나`, `-다` 접미사를 붙인다.
- 예: `ballotNumber: 1`인 후보가 2명이면 → 기호 1-가, 기호 1-나

`ballotNumber`가 0인 후보는 기호 표시 없이 이름과 정당만 표기한다 (교육감 등 기호 없는 선거).

### 표 형식

```
## [선거명] 후보 공약 비교

| | 기호 1 · [이름] ([정당]) | 기호 2 · [이름] ([정당]) | ...  |
|--|--|--|--|
| **공약 1** | **[공약 제목]**<br>[핵심 이행방법 1~2줄] | **[공약 제목]**<br>[핵심 이행방법 1~2줄] | ... |
| **공약 2** | **[공약 제목]**<br>[핵심 이행방법 1~2줄] | **[공약 제목]**<br>[핵심 이행방법 1~2줄] | ... |
| **공약 3** | **[공약 제목]**<br>[핵심 이행방법 1~2줄] | **[공약 제목]**<br>[핵심 이행방법 1~2줄] | ... |
| **공약 4** | **[공약 제목]**<br>[핵심 이행방법 1~2줄] | **[공약 제목]**<br>[핵심 이행방법 1~2줄] | ... |
| **공약 5** | **[공약 제목]**<br>[핵심 이행방법 1~2줄] | **[공약 제목]**<br>[핵심 이행방법 1~2줄] | ... |

※ 기호번호 순 정렬 / 판단·추천 없음
데이터 수집일: [meta.json의 collectedAt 값, YYYY-MM-DD HH:MM 형식]
```

규칙:
- 열 순서는 기호번호 오름차순으로만 배치한다.
- 공약이 5개 미만인 후보는 해당 셀을 `-`로 채운다.
- PDF 열람 불가 후보는 공약 셀 대신 `(선거공보 링크 참조)`를 표시하고, 표 아래에 `pbinfoUrl`을 별도 나열한다.
- 공약 제목은 AI가 PDF 내용을 해석한 결과를 간결하게 기재한다. 평가하거나 의견을 추가하지 않는다.
- **슬로건형 공약 제목 재레이블링**: PDF 공약 제목이 구호·슬로건 형태("압도적 교통개혁", "아이들의 상상이 미래가 되는 도시" 등)이면, 해당 공약의 핵심 정책 분야를 나타내는 중립적 명사형으로 변환한다.  
  예: "압도적 교통개혁" → "교통 인프라 개선", "아이들의 상상이 미래가 되는 도시" → "아동 교육 인프라 구축", "살기 좋은 화성" → "생활환경 개선"  
  원래 제목은 이행방법 줄에 괄호로 병기한다: `(원제: 압도적 교통개혁)`
- 핵심 이행방법은 PDF에서 읽은 구체적 방법·예산·일정을 1~2줄로 요약한다. 없으면 생략한다.
- 표 외에 어떤 평가·비교·판단도 추가하지 않는다.

### 기호번호 관련 안내

표를 출력한 뒤 해당하는 경우 즉시 다음 형식으로 안내한다:

**불연속 안내** — 기호번호 사이에 빠진 번호가 있으면:
```
※ 기호 [N]번 후보 정보가 수집 데이터에 없습니다. 이 선거구에 출마하지 않았거나 수집 중 누락되었을 수 있습니다. 정확한 후보 명단은 선관위(info.nec.go.kr)에서 확인하세요.
```

**중선거구 안내** — 기호 1-가/나 등 분할 표기가 있으면:
```
※ 이 선거는 중선거구제로 같은 정당 후보가 동일 기호번호를 공유합니다. 가/나 구분은 선관위 후보자 등록 순서 기준입니다.
```

해당 사항이 없으면 각 안내를 생략한다.

---

## Step 4.5: 페르소나 관련 요약 (조건부)

대화 컨텍스트에 `personaContext`가 null이거나 설정되어 있지 않으면 이 단계를 **완전히 건너뛴다**.

`personaContext`가 있는 경우:

1. `personaContext`에서 관심 분야 키워드를 1~5개 추출한다 (추가 PDF 읽기 없음 — Step 3에서 읽은 내용 활용).
2. 구분선과 함께 아래 형식으로 출력한다:

```markdown
---
## 페르소나 관련 요약 ([관심분야 키워드])

| | 기호 N · [이름] ([정당]) | 기호 N · [이름] ([정당]) | ... |
|---|---|---|---|
| [관심분야 1] | [해당 공약 1줄 요약] | [해당 공약 1줄 요약] | ... |
| [관심분야 2] | [해당 공약 1줄 요약] | ... | ... |
```

규칙:
- 행: `personaContext`에서 추출한 관심 분야 1~5개
- 열: 기호번호 오름차순 (Step 4 표와 동일 순서)
- 각 셀: 해당 분야와 관련된 공약 1줄 요약. 관련 공약이 없으면 `-`
- 금지 표현 목록 동일 적용 (`1위`, `가장 적합`, `추천`, `승자`, `점수`, `더 나은 후보`, `좋은 후보`)
- 비교·평가·순위 표현 불가 (예: "이 분야에서 [후보]가 더 구체적" 등)

---

## 종료

표 출력 후 추가 대화 없이 종료한다.
후속 안내(다른 선거 보기, 추가 정보 검색)는 `/pollens` 오케스트레이터가 담당한다.
