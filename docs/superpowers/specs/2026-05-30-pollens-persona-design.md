# pollens 스킬 페르소나 입력 기능 설계

**날짜:** 2026-05-30  
**범위:** `.claude/commands/pollens.md`, `.claude/commands/pollens-compare.md`  
**접근법:** Approach B — 두 파일 모두 수정

---

## 문제

`pollens.md`에 "경기도 화성시 동탄5동 유권자를 위한"이라는 페르소나가 하드코딩되어 있다. 다른 세션이나 다른 유권자가 스킬을 사용할 때 맞지 않는 맥락이 출력된다.

---

## 목표

- 페르소나/관심분야를 선택적으로 입력받는다 (스킵 가능).
- 페르소나가 있으면 비교표 아래에 페르소나 관련 요약 섹션을 별도로 출력한다.
- MD 보고서 자동 저장 옵션을 Step 4에 추가한다.
- 판단·추천 금지 원칙은 모든 신규 기능에 동일하게 적용된다.

---

## Section 1: `pollens.md` 변경 사항

### 1-1. 헤더 일반화

**변경 전:**
```
경기도 화성시 동탄5동 유권자를 위한 2026-06-03 지방선거 후보 공약 비교 오케스트레이터.
```

**변경 후:**
```
2026-06-03 지방선거 후보 공약 비교 오케스트레이터.
```

### 1-2. 새 Step 1.5: 페르소나 수집 (선택)

캐시 확인(Step 1) 직후, 읽기 모드 선택 전에 삽입.

출력:
```
분석에 반영할 관심분야나 페르소나가 있으면 알려주세요. (건너뛰려면 Enter)
예: "30대 워킹맘, 교육과 보육 관심", "스타트업 종사자, 경제·규제 관심",
    또는 Notion/URL 링크로 페르소나 문서를 공유해도 됩니다.
```

- 자유 텍스트 입력 → `personaContext`에 저장
- URL 입력 → 내용을 fetch해 요약 후 `personaContext`에 저장
- 빈 입력(Enter) → `personaContext = null`, 해당 기능 전체 비활성화

`personaContext`는 세션 전체에 유지된다 (세션 내 재질문 없음).

### 1-3. 기존 Step 1.5 → Step 1.6으로 이름 변경

읽기 모드 선택 단계를 Step 1.6으로 재번호 매김. 동작 변경 없음.

### 1-4. Step 2 출력 텍스트 일반화

**변경 전:**
```
경기도 화성시 동탄5동 기준으로 2026-06-03에 다음 선거가 예정되어 있습니다:
```

**변경 후:**
```
수집된 데이터 기준으로 2026-06-03에 다음 선거가 예정되어 있습니다:
```

Step 4a의 반복 출력도 동일하게 변경.

### 1-5. Step 4: MD 보고서 저장 옵션 추가

비교표 출력 후 후속 안내에 옵션 추가:

```
다른 선거도 볼까요? 이 후보들에 대해 추가 정보를 찾아드릴까요?
이 선거 분석을 MD 파일로 저장할까요?
```

MD 저장 선택 시:
- 파일명: `<PROJECT_ROOT>/<electionType>_후보_분석_<YYYY-MM-DD>.md`
- 내용: 비교표 + 페르소나 요약 섹션(있는 경우) + 출처
- 저장 후 경로를 사용자에게 안내

## Section 2: `pollens-compare.md` 변경 사항

### 2-1. 새 Step 4.5: 페르소나 관련 요약 (조건부)

기존 Step 4(비교표 출력) 직후, 종료 전에 삽입.

**조건:** `personaContext`가 null이면 이 단계를 완전히 건너뛴다.

**실행 흐름:**
1. `personaContext`에서 관심 분야·키워드를 추출 (별도 PDF 재읽기 없음 — Step 3에서 읽은 내용 활용)
2. 구분선 + 아래 형식으로 출력

**출력 형식:**
```markdown
---
## 페르소나 관련 요약 ([관심분야 키워드])

| | 기호 N · [이름] | 기호 N · [이름] | ... |
|---|---|---|---|
| [관심분야 1] | [해당 공약 1줄 요약] | [해당 공약 1줄 요약] | ... |
| [관심분야 2] | [해당 공약 1줄 요약] | ... | ... |
```

**규칙:**
- 행: 페르소나에서 추출한 관심 분야 (1~5개)
- 열: 기호번호 오름차순 (Step 4와 동일 순서)
- 각 셀: 해당 분야와 관련된 공약 1줄 요약. 없으면 `-`
- 금지 표현 동일 적용
- "이 분야에서 [후보]가 더 구체적입니다" 등 비교·평가 문장 불가
- `personaContext`가 URL에서 fetch된 경우: fetch된 내용에서 관심 분야 추출

## 불변 제약

- 금지 표현(`1위`, `가장 적합`, `추천`, `승자`, `점수`, `더 나은 후보`, `좋은 후보`) 모든 신규 섹션에 적용
- 스킬 파일 위치: `.claude/commands/` (project scope만 사용)
- 절대 경로 하드코딩 없음 — `git rev-parse --show-toplevel` 동적 처리
- 지역 레이블 테이블(`도지사→경기도` 등)은 meta.json의 실제 elections 배열을 기준으로 출력
